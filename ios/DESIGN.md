# 观羽 · Round 4

已逐张检查 `screenshots/round3-18pro/` 的 32 张验收截图，包括真实白头海雕、雪鹭；原图与标记正确，但小鸟难看清、事实在首屏下方、地点操作重复、地图确认有灰底及键盘干扰。本轮保留原生导航、系统字体和离线模型，新增视觉裁图，不改分类的像素规则。不使用所有者照片；测试照片仍是 `Tests/Fixtures/photos.json` 记录的 CC0 素材。

## 最终裁图规则（三句话）

从原始文件按 EXIF 转正后的像素坐标取鸟框，四边各加框长边的 35%（留出一点环境），只扩大短边，在 1:1、4:5、3:2 中选新增面积最小的窗口。原窗口长边不足 320 像素时最多放宽到 1.5 倍并标“鸟很小”（不再扩到 600 像素：小图源上那会把整张照片都框进来），窗口始终围绕鸟居中，遇边缘优先平移、仅在源图容不下时限制尺寸，保存绝不放大像素。显示裁图 `DisplayCrop.make` 与模型分类 `cropWithContext` / `Engine.crop` 分离；后者继续桌面共享的补色正方形规则，去背景只作用于展示和导出。

窗口在最后一步向外取整到源像素。很窄或本身小于 600 像素的照片可能无法满足指定比例或 600 像素目标，此时保留真实边界，不补造像素。旋转和镜像共八种 EXIF 方向均有逐像素回归。`CropCoordinates` 是原图归一化坐标与窗口归一化坐标之间唯一的正反变换；眼、嘴、蒙版实例选择共用它，8000 像素宽图的往返误差测试小于百万分之一像素。

检测结果按面积 × 检测分数选首只，先保留这一主体，余下按面积降序。IoU > 0.5 或交集超过较小框面积 90% 的检测视为重复，保留较强的一框。最多展示六张鸟图，原图仍画全部框并说明“还有 n 只”；被省略的框不冒充第六只。框和物种缓存的索引沿用同一顺序。

## 分页与第一屏

上方横向分页为“鸟 1 / 鸟 2 / … / 原图”，有系统页点和带标签的小缩略图；单鸟两页，无鸟只剩原图。切页选择相应主体，名称、事实、候选同步切换；原图保持最近选择，点可展示鸟的框跳至其页面。手动画框自动打开原图，完成后生成鸟 1。移除了照片控件里截获左右滑动的手势，由分页容器统一处理；双击与双指缩放保留。

鸟图页提供标记、按需去背景、保存、分享；原图页不提供保存或分享。标记总开关在分页下方。名称后立即给出在飞、本地频次、IUCN（含中文类别）和需要核对的提示，再给概率及地点/日期说明。普通字号画布高度 280 pt，最大辅助字号放宽到 560 pt；大字号允许滚动，不压缩文字。结果底栏合为一行“再选一张 / 改地点 / 删除”，`safeAreaInset` 实际占用高度参与 ScrollView 布局，正文额外留 24 pt 末尾空白；“改地点”只出现一次。无位置说明“没有位置，只凭图像。”仍原文保留，变成可点的设置入口。

首页地点为空时提供等宽、有图标的 bordered 定位/地图按钮；有地点时折叠为地点、来源、更改的一行摘要。（已更改）历史移到“记录 → 照片”，搜索和排序在任何条数下都可见。页首小鸟标记与“观羽”组成产品标识。地图确认使用全宽主按钮、纸色底；搜索提交收起键盘，底部操作随键盘安全区移动。原生 MKMapView delegate 报告实际瓦片加载/失败，搜索另有进度状态，不用固定延时假装瓦片已加载。大致位置圆圈为 25 公里。

地点来源说“按整个加利福尼亚州估计 / 按地图上选的位置”，不再说代表点；缺日期说“照片没有拍摄日期，按全年估计”。频次不代表实际种群数量，IUCN 与本地稀有是两回事；不确定、属级及当地资料缺失都明确说明。

## 去背景与导出

只在该鸟的“去背景”打开时，在后台对最多 1200 像素的显示裁图执行 iOS 17+ `VNGenerateForegroundInstanceMaskRequest`。从实例标签图中选择与检测框交集像素最多的实例；没有交集、覆盖不足 0.5% 或覆盖至少 95% 的蒙版均拒绝，关闭并隐藏该鸟的开关，保留矩形图和“未找到合适的轮廓”。失败与模拟器不支持也走同一回退。蒙版选择不调用鸟种模型。

**轮廓是 Apple Vision 的结果，可能切掉细腿、羽毛边缘或把背景一起留下；不是专业逐羽精修。** 显示在中性背景，透明蒙版按源裁图尺寸插值应用于原始像素；颜色图从不放大，蒙版分辨率与源图分辨率不同这一点不作隐瞒。[Apple 实例蒙版 API](https://developer.apple.com/documentation/vision/vninstancemaskobservation) 负责前景分离。

保存仅在点“保存到相册”后请求 PHPhotoLibrary 的 add-only 权限，配置 `NSPhotoLibraryAddUsageDescription`；拒绝不会影响识别。矩形导出 JPEG（质量 0.95），去背景导出带 alpha 的 PNG，均为源裁图像素尺寸。文件保留原照片的拍摄日期、时区偏移/亚秒、GPS；TIFF 描述、IPTC caption、EXIF user comment 写入当前物种名称（不确定时如实标注）。不复制旧 orientation、尺寸或嵌入缩略图；Photos asset 的拍摄日期和位置也设为原照片值，不用手选识别地点伪装原始 GPS。没有这些元数据时不编造。

分享使用 ShareLink 的异步 FileRepresentation，只有真正请求文件时才生成源尺寸文件，带相同元数据；不分享低清屏幕截图。保存临时文件随完成/失败删除，分享临时文件放在系统 tmp/BirdExports，之后每次导出清理超过 24 小时的文件，系统也可回收；它们不进入历史。

## 历史、解码与内存

一条历史永久文件仍为 **一个原始 `.photo` + 一个 JSON**，新增 `displayCrops` 是归一化矩形而非派生大图。老记录没有该字段仍可打开，按同一规则即时再生并在下次更新时补写。缩略图始终取鸟 1，不随当前选中的鸟改变。原始文件不被转码、改元数据或上传；一条记录的大小就是原文件字节数 + JSON（完整视觉概率缓存按已识别的鸟数量增长，与 round 3 相同），每个显示矩形通常只有约 80 字节。

ImageIO 以 `ShouldCache=false` 打开源图，先把 upright 窗口逆映射到原始方向并 `CGImage.cropping`，再只为该区域创建输出 CGContext；不把 48 MP 原图解成 UIImage / RGB 再制作六张大图。原图缩略图直接使用 ImageIO thumbnail + orientation API。每个缩略图限制 120 像素，只有当前页保留最多 1200 像素的显示图，离页释放；保存/分享一次只生成一个源尺寸裁图。解码器仍可能有内部缓存，真机 HEIC 峰值必须用 Instruments 复核，不能承诺 JPEG 的内存值也适用于 HEIC。

合成测试实际写出 8000×6000 JPEG，取 600 像素的小鸟窗口，核对输出尺寸、保存不放大并采样内存；不把生成合成大图本身的内存算成应用裁图内存。更改地点和分类依然使用原有模型路径，显示裁图不会反馈给分类模型。

## 视觉标识与对比度

颜色直接沿用桌面 `web/src/styles.css` 的松绿、纸色和琥珀；数值唯一来源 `ThemeContrast`，Palette 直接消费。正文/操作与纸色、卡片的浅深两组配对，全部 badge、按钮正常/按下/禁用的配对都保留 WCAG 4.5:1 自动测试。系统地图、系统权限框与照片内容不伪称受 token 对比测试覆盖。
