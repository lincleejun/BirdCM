# 实现与设计的出入

记录实现第 1、1.5、2、3 步时与 `design.md`（含第 9 节修订）不一致的地方和理由。

1. **解码方案选了第三种：RAW 内嵌的全尺寸 JPEG。** §9 要在 (a) 一次全尺寸解码、(b) 半尺寸 + 头部再全尺寸解码之间二选一。
   实测发现 A7 IV 的 ARW 里带一张 7008 × 4672 的相机 JPEG（`JpgFromRaw`，约 2.2 MB），用 Pillow 的 DCT 缩放解到半尺寸只要
   约 0.04 秒，而且只读文件的约 6%（主人的照片在 USB 机械硬盘上，读整个 39 MB 的 ARW 就要约 0.17 秒）。
   同样 120 张、4 个进程：内嵌 JPEG 50.8 张/秒，半尺寸解码 8.9 张/秒，全尺寸 3.7 张/秒（`perf.md`）。
   所以默认用 (c)，内嵌 JPEG 长边不到 2048 时（例如 Lightroom 导出的 DNG）回退到 (b) 的半尺寸解码。
   以后的头部清晰度可以直接在同一张全尺寸 JPEG 上裁头部，不需要再 demosaic；但它是相机处理过（降噪、锐化）的图，
   清晰度阈值要在它上面定，这一点留给清晰度调研确认。
2. **OWLv2 的处理器配置文件不进清单。** 上游 `config.json`（414 字节）除默认值外只有四个数，直接写在 `detect.py`；
   唯一的提示词 "a bird" 预先分好词（`[49406, 320, 3329, 49407]`）；图像预处理（灰 0.5 补成方形、缩到 960、CLIP 均值方差）
   在设备上自己做，比 `Owlv2Processor` 快得多。和 `Owlv2Processor` 对比过：同一帧的框位置差 < 0.005、把握差 < 0.03
   （`tests/test_models_smoke.py`）。效果等同于"写进清单并固定版本"，而且运行时完全不联网。
3. **`BIRDCM_MODEL_DIR` 可以是多个目录**（用 `:` 分隔），因为开发时模型分在 `release/` 和 `heads-repo-release/` 两处；
   缓存目录 `~/Library/Caches/BirdCM/models` 总是最后一个查找位置。每个文件都校验 sha256（按路径 + 大小 + 修改时间记住结果）。
4. **队列不是字面上的"三段有界队列"。** 只有一个调度线程，它同时是唯一的模型线程：解码任务提交给进程池，最多
   2 × 进程数个在途（这就是背压）；解码完的帧凑批（满一批、或第一张等了 200 毫秒、或后面没有了）送 GPU；exiftool
   在一个辅助线程上提前读。所有等待都带超时并检查停止标志，没有会永久阻塞的 `put/get`。停止时：不再提交，正在 GPU 上的
   那一批做完并提交，其余已解码或在途的结果丢弃，行退回 `queued`。这满足 §9 的语义，代码更少。
5. **检测模型在 GPU 上用 float16。** 120 张对比 float32：框数完全相同，主框 IoU 最小 0.994；速度快约 20%。
   BioCLIP 塔也是 float16，名录矩阵乘法和 softmax 用 float32；与 `examples/identify.py`（float32）在同一批裁图上前五与概率一致到小数点后两位。
6. **"不确定 / 只到属"规则（只凭图像，地区修正之前）**：第一名 ≥ 0.5 且领先第二名 ≥ 0.3 → 报到种；否则若同属概率合计
   ≥ 0.6 → 报到属；否则"不确定"。沿用 Gardener 的常量（`tower.py`），等地区修正接入后由调研结果替换。
7. **中文名**：`engine/birdcm/data/zh-names.csv`，取自 IOC 15.2 多语言版的简体 / 繁体中文列（CC BY 3.0，来源和署名见 NOTICE.md），
   覆盖 11,172 种中的 11,113 种（99.5%）；另有 2 行来自 Wikidata（CC0）。没有中文名的 59 种（多为 2025–26 年新拆分的种）显示英文名。
   与旧的 Wikidata 表冲突的 1,122 条一律取 IOC；6 个 AviList 合并种按英文名取对应 IOC 成员的中文名（如 *Pericrocotus flammeus* 赤红山椒鸟），
   *Butorides striata / virescens* 的 IOC 中文名疑似对调，前者留空、后者用 Wikidata 的“美洲绿鹭”。
   中文名在读出结果时按表填入（`names.py`），不进结果指纹；以后换表只需重启，不需要重扫。
   （把名字表移出指纹这一次本身会让指纹变一次：重启后已完成的扫描会标“结果过期”，但显示的中文名已经是新表的，不重扫也对。）
8. **对焦点**：`FocusLocation` 按它自带的宽高（7008 × 4672）归一化，不用 rawpy 的尺寸（7028 × 4688）。距中心一个像素以内的、
   宽高为 0 的、越界的都记为不可信。主人 1,947 张 ARW 里：65 张是中心默认值，3 张宽高为 0，没有缺失。
   这批和另外几个文件夹里都没有竖拍 ARW，竖拍的旋转映射只用单元测试（真实像素旋转）验证过，**未在真实竖拍照片上验证**。
9. **排队行**：按 §9 只显示文件名；选中排队中的照片时，按需从内嵌 JPEG 生成预览、用 exiftool 读拍摄信息。
10. **地区列表**只有名字（`app.py` 里的小表），代表坐标随 `geo.py` 一起来。
11. **一个扫描在最后一批时被停止**：照片都已处理但扫描停在 `paused`，按"继续"后立即汇总完成（有测试）。
12. **美学**：模型仓库没有发布的美学头，按 `distill/aesthetic.py` 的做法新写了 `distill/aesthetic_head.py`（只新增，不改旧文件），
    拟合并写出 `heads-repo-release/aesthetic.safetensors`（EVA 3,970 张、5 折 CV Spearman 0.754，留出的 100 张 0.831，取"短边 224 中心裁"的取景，
    因为它的 CV 略好于压扁）。引擎对整张照片再过一遍塔（只对没淘汰的照片）。EVA 的分数是 CC0，但图片本身的许可**没有查清**，见 NOTICE.md。

## 第二轮（Codex 中期评审之后，2026-11-17）

13. **"清楚的鸟"判断按框做，主体在通过的框里选。** 每张照片最多看 5 个框（按检测分），每个框各过一次塔；主体在通过把关的框里按对焦点 / 把握选。
    全部不通过时淘汰（"没有清楚的鸟"）。不通过的框不出眼、嘴、飞行。手动画框或"整张照片"重试时不经把关（人已经说了里面有鸟）。
    把关的门槛是在 MPS 上 float16 塔算出的向量上定的；引擎用的是同一条路（float16 塔、float32 归一化与余弦），没有在 float32 或 CPU 上验证过。
14. **头部清晰度的量法照搬 `distill/sharpness.py`（grad_ratio），但输入换了。** 调研用的是 Gardener 半尺寸 demosaic 的灰度图；
    我们用相机内嵌 JPEG 按 1/2 DCT 解出的灰度图（同样 3504 × 2336，但经过机内锐化和降噪）。所以**数值尺度不同，1.6 门槛不能照用**：
    默认不设任何清晰度门槛，只把分数存下来、在批内按百分位参与排名，界面写明"阈值未标定"。噪声在"框加 10% 余量"的裁剪图上估计（每张一样）。
    灰度图（约 8 MB）由解码进程传回主进程算清晰度，这是 §9"不跨进程传整张全尺寸 RGB"之内的做法（半尺寸、单通道）。
15. **标星的默认值就是记录下来的策略**（0.65 / 0.35、加减分、连拍组三星最多 2 张、按鸟种分名额、鸟种保底），没有在主人照片上调过；
    这套策略在主人两批照片上只比随机好一点（见 `bioclip-bird/notes/head-sharpness.md`）。所有数都在 `stars.Config` 里，随扫描存（和留片比例同一个字段），
    `PUT /api/scans/{id}/ratio` 可以改任一项并重算。与调研代码不同的三处：
    - 检测把握门槛用 0.3（OWLv2 自己的标尺，调研在主人照片上测试时也是 0.3；代码默认的 0.5 是另一个检测器的）；
    - 清晰度缺失不当作 0（§9 要求）：用美学百分位顶替，两样都缺时 Q = 0.5；
    - 连拍分组按相机分开（§9 提到多相机）。"已认出鸟种"= 到种一级且把握 ≥ 0.9（调研测试的口径），其余照片合成一个名额组。
    曝光扣分没有接（没有曝光测量），永远不触发。
16. **单张识别预览和按需预览用一个独立的小进程池**（2 个进程，30 秒超时，同一张照片只解一次），不和批量的解码池共用：
    批量池在调度线程里，按需预览要在扫描暂停、引擎还没加载时也能用。崩溃或超时只重建这个小池。
17. **结果指纹**现在包括：模型（角色 → sha256）、中文名表的 sha256、流水线版本、处理设置、地区。引擎加载时记下它实际用的清单摘要；
    调度器开始一个扫描前比对，不一致就把整个扫描的结果作废重算（不保留任何旧指纹下的结果）。
18. **上传照片的像素上限只查 JPEG / PNG**（Pillow 只读文件头）；RAW 在服务进程里不打开（LibRaw 只在工作进程里跑），只受 300 MB 体积上限约束。
19. 单张识别"补充地区"的控件在，选了地区会存进记录并重算，但地区修正还没接，所以**结果不会变**；界面上写明了。
20. **上传先看 `Content-Length`**，超过 300 MB 直接拒绝，不解析表单。限度以内的上传会先被 Starlette 写到系统临时目录（表单解析的做法），
    再由我们按块拷进数据目录并再次数字节；临时文件由 Starlette 清理。这是数据目录之外唯一会写的地方。
21. **星级设置在接口处校验**（未知字段、类型、范围、三星两星合计不超过 100%），不合法返回 400；万一库里存了坏设置，汇总时出错只把这个扫描标为
    `failed`，调度线程不会因此退出。

## 第三轮：鸟种质量与全球位置（2026-11-17 晚）

22. **地区修正**照搬 gardener 的公式，但模型直接用 BirdNET+ geomodel v3.0.4 的 ONNX 文件（onnxruntime），不依赖 `birdnet` 包；
    已核对两者结果完全相同（同一点、同一周差值 0；无日期时取 48 周最大值，和包一致）。AviList → 模型输出的对应表取自 gardener 的
    `avilist_map.csv`（10,344 个同名、84 个同义，744 个对不上的地区概率为 0）。range veto 已移植；71 个拆分种的范围表**没有移植**。
23. **位置面向全球**：一个点 + 名称 + 来源（照片 GPS > 地图选点 / 本机定位 / 地区代表点 > 无）。国家表（206 个国家和地区）和美、加、中
    三国一级行政区表是**手录的近似代表点**（±1–2°），没有用 Natural Earth（不想为一张表下载数据；以后可换）。
    点吸附到 0.05° 网格：模型是连续函数，实测 ±0.05° 内地区概率最多变 0.04（中位 0.014），所以挪图钉 100 米不重算；指纹用吸附后的点。
24. **"确认到种"的阈值**从 0.5 / 领先 0.3 改为 0.94 / 0，属一级 0.6 → 0.94，都在评测集上按鸟种分折交叉验证选出（docs/eval.md）。
25. **连拍组修正**在汇总时做（stars.py），结果存在每次扫描自己的列里（`species_fix`），照片自己的识别结果保留不动；界面和导出都标"按连拍组修正"
    并给出原来的名字和概率。多数的定义：支持某个种的帧（自己确认为它，或它在自己前五里）超过本组未淘汰帧的一半；并列时比概率和。
26. **稀有度**按点找地区：选的是地区就按名字精确对应；地图点 / GPS 按 Natural Earth 边界（简化到 0.02°）判断在哪个国家 / 一级行政区，离岸 0.15° 内算最近的那块，海上算"数据不足"（2026-11-17 改，之前用最近的代表点，温哥华会落到华盛顿州）。
    这是近似，靠近边界会对错（ponytail，等全球表时换成行政区边界）。表外国家显示"数据不足"。IUCN 用一个开关（`BIRDCM_IUCN=0`）整列关掉。
27. 地图图块是应用唯一的联网请求，只在打开地图对话框时加载；Leaflet 打包进前端（1.9.4，固定版本），不用 CDN。
28. **标星默认改为 `select`**（docs/stars.md），旧配额策略保留为 `strategy: "quota"`。同种衰减用 0.995 而不是讨论时举例的 0.985，是在合成场景上定的，
    没有用主人的照片。旧扫描存的 `{preset, p3, p2}` 读成同档位的新单一比例。在主人两批照片上，"有星"含留片的数量接近随机、不如 Gardener，3★ 的准确率是基准的 2–3 倍。
29. **地区修正按地点的不确定范围取先验**（`engine/birdcm/confirm.py`，docs/eval.md 第三轮）：选的地区用整片区域的格点（Natural Earth），
    点用周围 ±0.25°，时间取前后 3 周，后验用最大值；最大值 < 0.01 不确认（说明"图像最像 X，但此地此季几乎没有它"，候选不再挪位置），
    区域中位数 < 0.05 的确认结果标"本地少见 · 请核对"。讨论中的"图像很强 + 连拍一致可以推翻低先验"**没有做**：评测集上这种情况 31 张里 0 张对。
30. **Lightroom 衍生 DNG**（`-Enhanced-NR` / `-Enhanced-SR` / `-Enhanced-RD` / `-Enhanced`，旁边有同名 RAW，拍摄时间到秒和机身一致）算同一张照片：
    只分析和评星原 RAW，衍生文件列在右侧面板和导出的"衍生文件"列。HDR / 全景合成不算（不是一对一）。是否有衍生文件不参与评星。
31. **模型文件可缺**：clear / aesthetic / rarity 三个文件还没发布，缺了也能运行（不做"清楚的鸟"判断 / 不用美学分 / 稀有度显示"数据不足"），
    `birdcm models`、启动日志和首页都会说明。
32. **连拍组修正**（Codex E1）：一帧要对某个种的概率 ≥ 5% 才算支持它；已经确认成另一个种的帧不改（一组里可能有两只鸟）；没有证据的帧也不改。
33. **地区模型里没有的 744 个鸟种**（Codex C2）：先验算"未知"（后验里按 0.05），不再当作"这里没有"去否决。
34. **每种至少一张**（Codex E2）：也要过"质量太差不为凑数给星"的门槛；决策条显示其中有几张是保底。
35. **改留片比例**（Codex S2 / I2）：所有参数都校验范围；先用新设置算出星级，成功后再和星级一起保存，失败返回 400、什么都不变；汇总时发现设置变了就重算。
36. **被淘汰的照片也写鸟种**：淘汰只说明这张照片不留，不说明鸟是什么。没有通过"清楚的鸟"判断的照片，仍按选主体的规则取一个框，报它的鸟种；
    列表、右侧面板、导出都显示；按鸟种筛选时，只有选了"淘汰"/"不留"才会列出被淘汰的照片。
37. **"任选其一"**（Codex E3）只用在真的几乎一样的两帧上：同一鸟种、鸟在画面同一位置（±5%）、大小相差 ≤ 25%、主体 8×8 灰度缩略图几乎一样；
    只是清晰度和美学分接近时写"评分接近，选了那张"。阈值是保守的初值，没有在标注数据上校准。
38. **近似种来回跳**：同一组连拍里同一只鸟在两个同属种之间来回认（例如加州凤头燕鸥 / 皇家燕鸥），一个种占至少两倍帧数时按多数统一，
    并在决策条上单独列出"近似种来回跳，请核对 n"。
39. **改留片比例只改比例**（Codex I3）：其他评星设置保留；`{"replace": true}` 才整套替换。档位名跟着数值走。
40. **单张识别记录**带结果指纹，模型或规则变了会提示"旧版本算的"；重试失败时保留上一次成功的结果和它的地点、框（Codex I6 / I7）。
41. **手动改正鸟种**：右侧面板"改正鸟种"，可改这一张 / 这一连拍组 / 这批里所有被认成同一种的照片，可标为不确定、可撤销。改正按文件签名
    （路径、大小、修改时间）存，重扫、指纹变化后仍然有效；优先级：手动改正 > 连拍组修正 > 照片自己的结果，评星、稀有度、筛选、汇总、
    导出（"鸟种来源"列）和 eBird 导出都用它。改正过的照片不带"本地少见"等地区提示（那是对应用自己结果的判断）。
    `birdcm corrections export` 导出全部改正（文件、应用的鸟种、改正后的鸟种、范围），只作测试集，不用来调参。
42. **近似种请核对**也用于整组一致的情况：第一名的同属近似种在前五里（≥ 1%），且当地先验至少是第一名的两倍时提示（例如湾边的加州凤头燕鸥 /
    皇家燕鸥）。只提示，不改结果。


## iOS 观察记录 / 记录库（`design-lifelist.md` 第 1–3 步）

43. **迁移的断点续做用“逐文件事务 + 按记录 ID 跳过”代替清单和暂存库。** 每个旧 JSON 在自己的事务里写入；中断后重启，已写入的 ID
    跳过，最后一个事务统一定 canonical（同字节取最新 `(date,id)`）、冻结最早一次识别的日期回退、核对“记录 + 待修复 = JSON 文件数”和
    `integrity_check`，全部通过才设 `user_version=1`。效果与 §5.1 的清单相同，代码少得多。没有做“kill 在哈希/提交/完成中间”的注入测试，
    只测了 user_version 回到 0 后重跑不重复。
44. **旧记录的空间约为原来的 2.4 倍，直到所有者清理。** `legacy_json` 原样保留旧 JSON（含两份视觉向量），`model_json` 再存一份每只鸟的
    向量，`payload_json` 去掉向量；旧 JSON/`.photo` 文件也原样留着作恢复。“约 2.4 倍”是按一只鸟约 0.49 MB JSON 的估算，没有在真实迁移上测。“释放迁移恢复空间”按钮没有做（第 4 步之后再做，需先有已校验的完整备份）。
45. **同字节旧记录（别名）只保留、标注、不计数。** 结果页写“另有 n 个旧识别版本：同一照片，只统计一次”，并随备份导出；
    “把某个别名恢复为当前版本”的界面没有做。
46. **重新检测后对不上的旧主体直接退役（行与更正保留、不计入），不进入“需核对主体对应”。** 同一字节重新识别时检测是确定性的，
    IoU ≥ 0.5 一一对应都能接上，所以这条路实际只在换检测模型后出现。`needs_match` 列保留为 0。
47. **重新选择已删除照片的同一字节会直接恢复原记录（连同更正），不另外弹“恢复”确认。** 删除仍是墓碑，统计立即去掉。
48. **统计在 Swift 里对轻量行聚合，而不是 SQL 分组。** 列表只读框、主体状态和日期地点列（不读视觉向量）；1 万张 / 3 万主体是毫秒级。
    名录是否有这个学名在读取时判断，所以换名录后结果跟着变。
49. **整组“本次观察数量”覆盖只在存储与统计层实现（`ll_group_edit`，测试覆盖），界面入口放到第 4 步的观察记录列表。**
    改日期/地点后旧覆盖留在原组键上不生效（即规格里的“dormant”），没有提示文字。
50. **编辑不做 `expected_revision` 冲突检查。** 只有一台设备、一个写连接、无同步；修订号照常递增，未来同步适配器再用。
51. **导入合并：本机记录 ID 已存在的一律保留本机；同字节、不同 ID 的导入记录作为别名加入；不做逐字段冲突选择界面。**
    再次导入新增 0。替换（restore）前自动写 `safety-before-restore.birdcm` 到记录目录。备份结构校验是逐对象比对 `sqlite_master.sql` 文本与
    本版建表语句完全一致，多一个表/索引/触发器都拒绝。
52. **搜索没有拼音。** 中文、英文、学名三名 NFKC + 大小写/变音折叠，精确 > 前缀 > 包含；拼音留到第 4 步与探索的“这里这个月”一起做。
53. **鸟种页没有 eBird 链接**（需要打包 `ebird-names.csv`，与 eBird CSV 一起在第 4 步做）；保留维基百科学名搜索和复制学名。
54. **模拟器上不调用 Apple Vision 去背景，直接显示“此设备不支持”。** 规格要求不把模拟器回退冒充 Vision 成功；
    Debug 参数 `-maskFixture success|none|unsupported` 注入三种状态，成功夹具明确标“测试夹具蒙版，不是 Apple Vision 结果”。真机效果仍需在 iPhone 上验。
55. **拍照在模拟器上只能验证“没有相机”状态和 `-cameraFixture` 注入的同一接收流程**；权限拒绝分支、真机元数据需真机验证。
56. **文件保护用系统默认的 complete-until-first-unlock，并在新目录/原图上显式设置；目录的“不备份”标记被清除。**
57. **迁移只把内容问题（JSON 解不开、违反约束）放进待修复；读原图失败等 I/O 错误直接中止、不设 `user_version`，下次启动重试。**
    迁移失败时只提供“重试”，没有做只读恢复浏览和“导出旧文件”入口（旧文件原样留在 History 目录）。
58. **原图缺失的旧记录可以在列表、统计中出现（标“原图不可用”），但打不开结果页，因而不能在应用里更正或排除。**
59. **JSON 损坏的旧记录：原始 JSON 字节随备份导出，但它旁边的 `.photo` 不进 `.birdcm`**（备份只按 `ll_asset` 写原图）。
60. **删除 / 清空只写墓碑，原图文件留在记录目录，没有“清理本机空间”入口。** 存储占用在设置里如实显示。
61. **模型给到种但“特征不清楚”（clear=false）存为 `model_level=uncertain`、不存学名**；原判断完整保存在 `model_json`，界面仍显示。
62. **照片搜索不再匹配模型前五候选**，只按有效鸟种（更正优先）的三名、地点和日期；避免把未确认的候选当成记录。

## 桌面端：全球稀有度表与记录本

63. **全球稀有度表**（`rarity-global.sqlite`，还没发布，`models.toml` 里是可选、`released = false`，放进 `BIRDCM_MODEL_DIR` 或模型缓存
    就用）：装了就替代美国 / 加拿大 / 中国表。坐标 → 地区只有一个入口 `rarity.place_region`：有全球表时用表里的 `shapes`
    （`rarity_global.region_at` 的移植，21 个自检点、iOS 的 8 个参照点都对上），没有时用随引擎带的 Natural Earth 轮廓；稀有度、
    eBird 的州 / 国家代码、评测标签、记录本都走它。地区一律用 ISO 3166 代码（地点列表里的国家和州 / 省也带代码，选地区时存下来）。
    一级区当月没有自己的数时用本国同月，标"按全国数据估计"；`source_id` 为空是"数据不足"，不是"无记录"。只装旧表时照旧只覆盖三国，
    其他地方"数据不足"，状态里写明"没有全球稀有度表"。旧表结果里的地区码也换成 ISO（原来是 GADM 编号，如 `CHN.2_1`）。
    这个条目在清单里加了 `neutral_when_absent`：没装时结果指纹不变（不让所有扫描都变成"旧版本算的"）；装上后指纹变了，
    之前的扫描会提示需要重扫——稀有度进了评星，这是如实的。
64. **记录本 / 统计（docs/design-lifelist.md 第 5 步，桌面端）**按规格做了派生索引、接口、页面、`.birdcm` 导入导出和 eBird；
    下面是为了代码量做的简化，每条都不改变计数规则：
    - 一张照片同时出现在多个来源（两个扫描范围、扫描 + 认一张、导入）时只取一份结果：有人工更正的来源优先（导入 > 认一张 > 扫描），
      否则取最新的；**没有**"两边都有人工更正就标为冲突、让人选来源"的界面。照片仍只算一次。
    - 扫描视图里的改正（`correction` 表）和记录本里的鸟种更正（`ll_subject_edit`）都存在时，**较新的那个生效**；记录本里更正主体鸟时
      也同步写一份扫描视图的改正（两边说法一致）。
    - 重新检测后的主体对应：桌面端主体编号由照片哈希 + 框（6 位小数）得出；框变了编号就变，旧编号上的数量 / 排除编辑不会自动挪到新框，
      也不进"需核对主体对应"列表（没有 IoU 匹配迁移）。导入时文件里的编辑按同编号或 IoU ≥ 0.5 对到本机的框。
    - 检测框不再做重叠去重（检测器已去重）；"清楚的鸟"判断为否的框既不计数也不算待确认（否则每张照片 5 个框里的杂框都会变成待确认）。
    - 没有拍摄日期时一律记 `date_source=identified`（按首次识别时这台电脑的时区），不区分 `identified_legacy_zone`。
    - 汇总在 Python 里按代做内存计算（按 generation 缓存），不是逐条 SQL 聚合；1 万条证据在毫秒级。
    - 导入：同一份记录（同 UUID）再导入直接跳过，不比较 revision；本机已有的照片只作为来源别名（canonical=0）保存，冲突只比较同一主体的
      鸟种 / 数量 / 排除和整张照片的日期 / 地点，默认保留本机。恢复（restore）先自动导出一份安全备份到数据目录 `backups/`，
      再清空导入记录和记录本编辑后合并；扫描表不动；导入文件夹里不再被引用的原图不清理。没有删除照片 / 墓碑（tombstone）功能。
    - 网页：没有"识别其余 n 只"、选封面、懂鸟链接（没有确认过的公开网址）；照片详情是一个对话框（预览 + 鸟种 / 数量 / 排除 / 日期 / 地点），
      扫描来的照片可"在批量选片中打开"。地图按视野网格聚合（最多 500 处），只选地区和地点未知的记录列在地图下面。
    - 性能没测 10k 照片的预算；在主人数据库副本上的实际耗时见交付说明。

## iOS 第 4 步（统计、探索、eBird、文件夹备份）

65. **iOS 与桌面格式的出入（已在 iOS 一侧改正）**：(a) iOS 第 1 步导出的 `.birdcm` 多了一张 `ll_meta` 表（§8 规定只有 5 张 `ll_*` 事实表），
    导入时也要求它，会拒绝桌面文件；现在导出不写、校验不要求。(b) 旧记录主体 ID 原用 UUID 版本位 `0x40`，共享约定是 `0x50`
    （`stable_uuid`）；现在统一为 `0x50`。已经用旧版本迁移过的手机上，主体 ID 是存下来的，不会改变；ID 只作不透明标识，两端不重新推导它。
    (c) 数量改成 1 时现在存为"未修改"（共享约定：只有不等于 1 才写 `count_edit`）。其余建表语句与桌面逐字相同。
66. **从桌面导入的记录可以列出、统计、更正，但结果页只按列显示**（框、日期、地点、模型级别），看不到桌面的完整识别结果；
    在结果页改地点会写一份 iOS 格式的 payload 覆盖那条记录的桌面 payload（原样保存在导出的桌面文件里）。
67. **日历缩略图只做内存缓存**（按需从原图解码小图），没有 100 MiB 磁盘缓存；原图缺失的日期显示带底色的种数格。
68. **本地稀有度按“鸟种 × 地点格（约 1 km）× 月”缓存**，同一格里跨行政区边界的少数点按第一张照片的地区算。
69. **地图**：按当前视野网格聚合，圆点数字是不同观察记录数；只选地区的记录列在地图下方，不画行政区轮廓；无法检测底图是否加载，
    说明文字写明底图需要网络、列表离线可用。
70. **探索“这里这个月”**：只用首页地点（不另存“探索地点”）；稀有度筛选按探索的地点和月份；没有保存目标 / 提醒。
    拼音用 Foundation 的普通话转写，多音字可能不准，只作便利。
71. **eBird**：数量只有“全部 X”或“全部用估计数量”两种，没有逐种编辑；没有提供 Stationary。名录里没有对应英文名的种只写学名。
72. **文件夹备份**的“已校验”= 本地导出文件完整校验后、写入文件夹的字节数与之相同；不从文件提供方重新读回校验。
    “本应用写的文件”按记在本机的文件名清单判断。只在 App 回到前台时运行，前台时间不够时可能留下未完成的副本（不会删除旧备份）。
73. **“清理旧版本副本”只删除升级前的 JSON 文件**，并且只删除内容已逐字节存在记录库里的那些；不删除任何原图。
