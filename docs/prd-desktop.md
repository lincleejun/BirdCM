# 需求文档：PC / Web 版（批量选片）

状态：草稿，2026-11-17。写给主人确认。标了"待定"的地方需要主人拍板，标了"未验证"的数字还没在真实照片上量过。

## 1. 要解决的问题

一次拍摄回来约 1,500 张原片，想快速筛到约 200 张，并知道每张拍的是什么鸟。
现在的 Gardener 能做，但模型合计约 8 GB，流程杂。这一版把流程收成一条线，模型压到 1 GB 以内。

## 2. 用户和场景

- 用户：主人自己（长焦拍鸟，索尼 A7M4，原片是 ARW）。
- 场景：拍完回家，在电脑上选一个文件夹，等它跑完，看结果列表，挑片，导出。
- 每周约两次，每次约 1,500 张。

## 3. 流程

1. **选文件夹**，给拍摄地点（全球任何地方：用本机定位、在地图上点一下，或选国家 / 一级行政区；不必精确，也可以不给），选**留片比例**。
2. **找鸟**：检测模型给出每只鸟的框。多只鸟时用相机记录的对焦点选主体。
3. **看鸟**：BioCLIP 一遍给出鸟种、眼和嘴的位置、是否在飞。
4. **美学分**：BioCLIP 对整张图再跑一遍。
5. **结合地区和日期**：用 BirdNET 的地理数据修正鸟种。
6. **稀有度**：查 GBIF 记录数（当地、当月）和 IUCN 受威胁等级。
7. **标星**：同一批照片互相比较，按比例给 1–3 星（策略见 `notes/star-strategy.md`）。
8. **结果列表**：见第 5 节。
9. **导出**：见第 6 节。

不做的事：不认兽类；姿态只分"飞 / 不飞"；不改、不移动、不删除原片。唯一会写进照片文件夹的是你点了才写的 XMP 边车（见第 6 节）。

## 4. 功能要求

### 4.1 输入
- 一个文件夹（只看顶层，除非选了"包含子文件夹"）。支持 ARW、DNG、JPG。
- 拍摄地点：面向全球。三种给法：本机定位（浏览器申请位置权限）、在地图上选点（OpenStreetMap，打开地图时才联网）、
  选国家 / 一级行政区（离线可用，用它的代表点）。照片自带 GPS 时以照片为准。不给地点也能用，只是鸟种只凭图像判断。
- 留片比例（参考慧眼选鸟的档位）：

  | 档位 | 三星 | 两星 |
  |---|---|---|
  | 宽松 | 前 40% | 其后 30% |
  | 标准（默认） | 前 30% | 其后 30% |
  | 严格 | 前 20% | 其后 30% |
  | 自定义 | 自己填 | 自己填 |

  主人实际留片率约 8%–10%，所以可能还需要一个"更严"的档。**待定。**

### 4.2 处理
- 全程本地运行，不上传照片。
- **没有单独的进度页（主人 2026-11-17 定）：** 点开始直接进结果页，照片像队列一样先全部列出来，出一个结果显示一个，一批一批更新；顶部一条状态显示扫到第几张。星级要全部扫完后才给。可以中途停止，下次接着跑。
- 没有鸟的照片、鸟太小太糊的照片单独归为"淘汰"，不占星级名额。
- 连拍分组：拍摄时间间隔 2 秒内算一组；同一组里三星最多 2 张。
- 每个认出的鸟种至少保住一张两星以上。

### 4.3 性能目标（M4 Max，未验证的是目标不是实测）
- 1,500 张原片在 15 分钟内跑完。（未验证。现在解码每张约 0.8 秒，BioCLIP 每秒 33–40 张，瓶颈在解码。）
- 模型合计不超过 1 GB。（BioCLIP 8 位版 0.63 GB 已验证；检测模型 15–156 MB，见第 7 节。）
- 鸟种第一名命中不低于 91%（评测集 1,046 张；92.4% 是 PRD 初稿的数字，早于 BirdCM 自己的评测，来源和配置未记录。BirdCM 自己的评测：照片坐标、规范口径第一名完整配置 91.20%、发布版配置 91.40%，见 `docs/eval.md` 第五轮）。

## 5. 结果列表

每张照片一行，可以按星级、鸟种、是否飞版、稀有度筛选和排序。

| 字段 | 说明 |
|---|---|
| 缩略图 | 画出鸟的框、眼睛位置、对焦点 |
| 星级 | 0–3 星，或"淘汰"，附一句理由 |
| 鸟种 | 中文名、英文名、学名、把握；分不清时只报到属 |
| 候选 | 前 5 个可能的鸟种 |
| 是否在飞 | 是 / 否 |
| 眼睛 | 看得见 / 看不见；眼部清晰度 |
| 美学分 | 0–1（只供参考，见第 8 节） |
| 稀有度 | 当地当月：常见 / 不常见 / 少见 / 罕见；IUCN 等级 |
| 连拍组 | 组号，组内排名 |
| 拍摄信息 | 相机、镜头、焦段、光圈、快门、ISO、曝光补偿、对焦模式、时间、地区（主人 2026-11-17 定） |

顶部给一个汇总：共多少张、各星级多少、认出多少种鸟、其中少见和罕见的有哪些。

## 6. 导出

- CSV 和 JSON，字段同上。
- eBird 清单（每个鸟种一行、数量、日期、地点），见 `docs/ebird.md`。
- 把星级和鸟种写进 XMP 边车，给 Lightroom 用（主人定的做法 A）：明确的导出动作，默认不做；点了、看过要新增 / 修改几个文件并确认后，
  才在每张 RAW 旁写同名 `.xmp`，不改原片本体，已有的 `.xmp` 只加改我们的字段，可撤回。字段和依据见 `docs/deviations.md`「XMP 边车」。
- **待定**：自己看的网页报告。

## 7. 用到的模型

| 环节 | 模型 | 体积 | 状态 |
|---|---|---|---|
| 找鸟 | 待定：OWLv2 8 位版（156 MB）或 D-FINE / RT-DETR（15–172 MB） | 见左 | 对比进行中 |
| 鸟种 | BioCLIP 2.5 看图部分，8 位 | 0.63 GB | 已验证，92.4%（PRD 初稿的数字，来源和配置未记录；BirdCM 评测见 `docs/eval.md`，注明了完整 / 发布版配置） |
| 眼和嘴 | BioCLIP 第 15 层上的小头 | 1.3 MB | CUB 测试集 98%；主人照片上清楚的单只鸟可用 |
| 飞 / 不飞 | BioCLIP 第 15 层上的小头 | 几 KB | 没见过的鸟种上 97% |
| 美学 | BioCLIP 第 15 层上的小头 | 几 KB | 和现有的相当 |
| 地区修正 | BirdNET 地理数据 | 已有 | 已在用 |
| 稀有度 | GBIF 记录数 + IUCN 等级的表 | 估计几 MB | 生成中 |

不再需要：SigLIP2（1.5 GB）、BioCLIP 的文字部分。

## 8. 已知问题和风险

- **检测框里没有清楚的鸟时，眼、嘴、飞行都会乱给结果。** 需要一个"框里有没有清楚的鸟"的判断，还没做。
- **美学分只比随机好一点。** 在主人 1,947 张照片上，按美学分取前 13% 只包含留片的 24%。它不能单独用来选片。
- **标星策略没验证过。** 之前的结论是"组里哪张最好"上 Gardener 和慧眼选鸟都接近随机。新策略要用主人的 Lightroom 留片来检验（只测不训）。
- **头部清晰度还没有。** 标星 65% 的权重靠它，要基于眼睛位置新做。
- 小检测模型对很远很小的鸟不如 OWLv2，见对比结果。

## 9. 验收

- 评测集上鸟种第一名不低于 91%，找到鸟的比例不低于 97.5%。
- 在主人的一批照片上：留片比例设成和主人实际留片率相同时，选出的照片包含主人留片的比例，高于现在的 Gardener 和慧眼选鸟。（基线数字在 `notes/culling-bench`。）
- 1,500 张跑完不超过 15 分钟。
- 扫描全程不写入照片所在的文件夹；只有你确认的「写 XMP 边车」会在里面新增 / 修改 `.xmp`（原片字节不变，可撤回）。
