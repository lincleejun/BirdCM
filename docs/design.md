# BirdCM 方案设计（web 第一版）

状态：草稿，待 Codex 评审。产品需求见 `prd-desktop.md`、`prd-mobile.md`，界面见 `prototype/`。
标了"待调研"的三处在等结果（头部清晰度与标星验证、"框里有没有清楚的鸟"、稀有度表与地区修正），接口先按本文占位。

## 1. 已定的事（主人 2026-11-17）

- 形态：本地网页 + 本机 Python 引擎。照片不离开电脑，原片文件夹只读。
- web 第一版 = 桌面批量选片 + 选一张照片识别。手机端以后做原生，不在本版。
- 上千张照片要走队列，界面实时看到进展，可停、可续。
- 第一版要全：找鸟、鸟种、眼嘴、飞 / 不飞、美学、地区修正、稀有度、头部清晰度、标星、CSV / JSON 导出。
- 模型不进仓库：一张清单（地址 + sha256）可配置，安装或首次运行前下载。发布在 GitHub Release；
  上线前开发指向本地目录。
- 代码 MIT。眼嘴 / 飞行小头权重和 BirdNET 地理数据仅限非商用，只下载、不入库，README 写明。
- 标星逻辑自己写，不读不抄慧眼选鸟（AGPL）。不用 YOLO（AGPL）。
- 仓库和代码叫 BirdCM，界面中文名"观羽"。

## 3. 引擎

### 3.1 一张照片的处理

1. **解码**（CPU 进程池）：ARW / DNG 用 rawpy，JPG 用 Pillow。出三样：
   缩略图（长边 512，存缓存目录）、识别用的帧（长边 ≤ 2048，摆正）、原尺寸像素留给清晰度裁头部用。
   同时读拍摄信息：相机、镜头、焦段、光圈、快门、ISO、曝光补偿、对焦模式、时间（含亚秒，连拍分组要用）、GPS、
   索尼对焦点（`Sony:FocusLocation`）。
   - 拍摄信息用常驻的 `exiftool -stay_open` 批量读（对焦点就是用它验证的，49 / 49）。exiftool 是系统依赖，
     缺了给出明确的安装提示。`ponytail:` 以后可换成纯 Python 读 0x2027，去掉这个依赖。
   - 解码是瓶颈（实测每张约 0.8 秒）。先量"半尺寸解码 + 只对头部区域取原尺寸"能否达标，再定是否需要全尺寸。
2. **找鸟**（GPU，成批）：清单里选定的检测模型，默认 OWLv2 8 位。多只鸟时用对焦点选主体
   （对焦点在某个框内或 3% 以内取该框，否则取把握最高的）；其余框保留，界面可看。
3. **看鸟**（GPU，成批 32）：每个主体框取方形裁剪图过一遍 BioCLIP 8 位塔，同时得到：
   - 鸟种：图向量 × 名录矩阵（11,172 种）→ 前 5；
   - 第 15 层 256 个小块 → 眼嘴位置与可见度、P(飞)、"清楚的鸟"判断（待调研）。
4. **美学**（GPU，成批）：整张图再过一遍塔，第 15 层小块平均 → 线性头。
5. **地区修正**：照片 GPS 优先，否则用所选"国家 + 州 / 省"的代表坐标，加拍摄周 → BirdNET 地理先验 →
   与鸟种概率合并（合并方式沿用 Gardener，待调研确认）。分不清时只报到属。
6. **稀有度**：表里查"该地区、该月"的档位和 IUCN 等级（表格式和分档规则待调研）。
7. **头部清晰度**：眼睛周围原尺寸像素上算，按 ISO 归一（待调研）。
8. **淘汰判断**：没有框，或"清楚的鸟"不通过 → 标为淘汰，眼嘴和飞行留空，不占星级名额。

`pipeline.py` 对外只有一个入口：`run(paths, region) -> Iterator[PhotoResult]`，批量扫描和单张识别共用。
设备选择：mps → cuda → cpu。先保证 macOS，其他系统能跑但不承诺速度。

### 3.2 队列

目标：1,500 张时界面立刻可用、进度实时、能停能续、引擎重启不丢结果。

- **状态存 SQLite**（标准库 `sqlite3`，文件在 `~/Library/Application Support/BirdCM/`，可用环境变量改）：
  - `scan(id, folder, recursive, region, ratio, state, created_at)`
  - `photo(id, scan_id, path, size, mtime, seq, state, result_json, error)`，
    state ∈ `queued / working / done / failed`；`(scan_id, path)` 唯一。
  - `event(scan_id, n, photo_id)`：每完成一张记一条递增序号，给断线重连用。
- **建扫描**：只列文件（不解码），一次写入全部行，立即返回。界面马上能列出全部文件名。
  缩略图和拍摄信息在各自那张处理到时才有；排队中的行先只显示文件名。
  （原型里排队行就有缩略图和参数。`ponytail:` 如果主人要这个，加一遍只做缩略图 + 拍摄信息的快速预扫。）
- **工作方式**：一个扫描一个后台线程，三段用有界队列相连，互相背压：
  解码进程池（CPU 核数 − 2）→ GPU 批处理（凑满 32 张或等 200 毫秒）→ 后处理并写库。
  同一时间只跑一个扫描，其他的排队。
- **停止 / 继续**：停止 = 置标志，在跑的那一批做完后停，`working` 的行退回 `queued`。
  继续 = 接着跑 `queued` 的行。引擎启动时把残留的 `working` 退回 `queued`。
  再次扫同一个文件夹：`(path, size, mtime)` 没变的行直接复用结果。
- **星级**：全部 `done / failed` 后调 `stars.py` 算一次，写回各行。改留片比例只重算星级（毫秒级），不重扫。
- **失败**：单张解码或识别出错只标该行 `failed` 并记原因，不影响其他照片。

### 3.3 接口（只监听 127.0.0.1）

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/api/regions` | 国家和州 / 省列表 |
| POST | `/api/pick-folder` | 弹系统选文件夹窗口（macOS 用 `osascript`），返回路径；界面同时允许手输路径 |
| POST | `/api/scans` | `{folder, recursive, region, ratio}` → 扫描 id |
| GET | `/api/scans` / `/api/scans/{id}` | 列表 / 完整快照（全部行 + 汇总 + 最新事件序号） |
| GET | `/api/scans/{id}/events?after=n` | 事件流（SSE）：每张完成推一条结果，另有进度和完成事件 |
| POST | `/api/scans/{id}/stop` `/resume` | 停止 / 继续 |
| PUT | `/api/scans/{id}/ratio` | 改留片比例，重算星级 |
| GET | `/api/photos/{id}/thumb` `/preview` | 缩略图 / 大图（按 id 取，不接受路径） |
| POST | `/api/identify` | 上传一张照片 → 结果，自动记入历史 |
| GET / DELETE | `/api/history` `/api/history/{id}` | 单张历史：列表、删一条、清空 |
| GET | `/api/models` | 模型是否就绪、缺哪些 |

- 实时进度用 SSE（浏览器原生 `EventSource`，自带重连）。重连时带上已收到的序号，引擎补发之后的事件。
- 导出在浏览器里生成（行数据本来就在页面上），CSV 带 BOM，同原型。
- 安全：只绑 127.0.0.1；校验 `Host` / `Origin` 是本机，防别的网页借浏览器访问；
  图片接口只按数据库里的 id 取文件；除缓存目录和数据目录外不写任何地方。

## 4. 模型清单与下载

`models.toml` 每个文件一条：

```toml
[detector]
use = "owlv2-int8"                     # 可换成清单里的其他检测模型

[[file]]
name    = "bioclip-2.5-vith14-visual-int8.safetensors"
url     = "https://github.com/<owner>/bioclip-bird/releases/download/<tag>/…"
sha256  = "126ea3…"
bytes   = 633415546
license = "MIT"
```

- `birdcm models fetch`：缺的才下，流式下载到临时文件，sha256 对上再改名到模型目录
  （默认 `~/Library/Caches/BirdCM/models`）。`birdcm serve` 启动时检查，缺文件就在界面上提示并给出这条命令。
- 开发期：`BIRDCM_MODEL_DIR=/…/bioclip-bird/release` 直接指本地目录，同样校验 sha256。
- OWLv2 的处理器小配置文件（现在从上游拉）也写进清单并固定版本，运行时不隐式联网。
- 清单包含：BioCLIP 8 位塔、名录矩阵、检测模型、眼嘴头、飞行头、"清楚的鸟"头（若有）、美学头、稀有度表、
  BirdNET 地理数据（若它由 pip 包自带则不列）。

## 5. 界面（web/）

- Vite + React + TypeScript。不引状态库、路由库、组件库；样式从原型的 CSS 变量和类名搬过来，浅色 / 深色跟随系统。
- 三个视图，用一个状态变量切换：选片设置 → 审片结果（队列）→ 单张识别与历史。
- **审片结果**完全按 `prototype/desktop.html`：状态行、汇总、筛选排序、列表 + 右侧预览、详情弹窗、导出弹窗、键盘操作。
  数据来自一次快照 + 事件流增量。1,500 行用 CSS `content-visibility: auto` 省掉屏幕外的绘制；
  `ponytail:` 实测卡再上虚拟列表。
- **单张识别**：选文件或拖进来 → 上传给本机引擎 → 结果页按 `prototype/mobile.html` 的结果页布局
  （照片在上，信息在下顺序排），自动进历史。没有星级。多只鸟切换、手动画框重试、补充地区按原型。
- 模型没下好时，首页显示缺哪些和下载命令。

## 6. 测试与验收

- 纯逻辑的单元测试：标星（名额、连拍上限、鸟种保底）、连拍分组、稀有度分档、对焦点选主体、
  队列（用假的 pipeline 测停止、继续、重启恢复、复用结果）。
- 真模型冒烟：模型目录存在时，跑几张评测照片，核对前五和 `examples/identify.py` 一致。
- `birdcm eval`：在评测集上出"找到鸟"和"第一名命中"，对 PRD 的 97.5% / 91%。
- 验收（PRD 第 9 节）：评测集两项指标；主人一批照片上的留片对比；1,500 张 ≤ 15 分钟；
  扫描前后原片文件夹的文件列表和修改时间不变。

## 7. 实现顺序

1. 引擎骨架：清单与下载、解码与拍摄信息、找鸟、看鸟，`birdcm scan <文件夹> --json` 能在命令行跑通。
2. 队列、SQLite、接口、事件流。
3. 桌面界面接真数据。
4. 接入调研结果：清楚的鸟、头部清晰度、地区修正、稀有度、标星。
5. 单张识别与历史。
6. `birdcm eval` 与验收。

## 8. 想请评审重点看的

1. 队列设计（三段 + SQLite + SSE 补发）有没有会丢结果、卡死或重复处理的地方。
2. 解码策略：半尺寸解码 + 头部原尺寸是否可行，1,500 张 15 分钟的风险在哪。
3. exiftool 作为系统依赖是否可接受，还是第一版就该纯 Python 读。
4. 本机服务的安全面（Host / Origin 校验、按 id 取图）是否够。
5. 前端用 React 是否过重；原型是单文件原生 JS。
6. 有没有可以删掉的部分。

## 9. 评审后的修订（Codex，2026-11-17；与前文冲突时以本节为准）

评审原文：`design-review.codex.md`。逐条采纳如下。

**队列与恢复**
- 全进程只有**一个调度器、一个模型工作线程**。扫描状态持久化：
  `queued → running → stopping → paused → finalizing → completed`（另有 `failed`：致命引擎错误）。
- 停止：先停止领取新照片，在途批次做完并提交，其余在途输出丢弃，然后才进入 `paused`。`stop` / `resume` 幂等，
  不会起第二个消费者。段间队列的读写都带超时并检查停止标志，不用无限阻塞的 `put / get`。
- 每张结果的写库与事件写入在同一事务，提交幂等（按 photo id 覆盖）。
- `finalizing` 持久化：启动时，照片都已终结但扫描未 `completed` 的，重新分组、标星（确定性）。
  空文件夹、全失败、全淘汰都要正常终结。
- 结果复用要带**版本指纹**：文件签名（size, mtime）+ 模型与数据文件的 sha256 + 处理配置 + 有效地区。
  指纹不同就重算，不做分层缓存。星级和连拍组永远按当前扫描重算。处理前复查文件签名，变了或没了就报错。
- 进程池崩溃（LibRaw 原生崩溃）要重建池并隔离坏文件（有限重试）；GPU 批次 OOM 缩小批次重试，不把整批标坏。
  解码和 exiftool 设超时。SQLite 单写线程、短事务；SSE 不长期持有读事务。

**事件流**
- 事件类型只有三种：`photo`（一行变更）、`scan`（状态 / 进度变更）、`stars`（星级重算完成，客户端重取快照）。
- 每条带 `id: n`；重连优先读 `Last-Event-ID`，其次 `after`。快照和游标来自同一个读事务。
- 客户端按序号去重，扫描完成后主动断开。慢客户端或关页面不影响扫描。

**解码与性能（先量再定，排在界面之前）**
- 两个候选实测后二选一：(a) 一次全尺寸解码；(b) 半尺寸解码出帧，找到鸟后在工作进程里对该照片再全尺寸解码，
  **只返回头部小块或清晰度值**。任何方案都不跨进程传整张全尺寸 RGB。流程里因此有一段"GPU 定位之后的 CPU 清晰度"。
- 性能验证是实现的第 1.5 步：代表性 ARW 跑完整链路，再跑 1,500 张，记录各段吞吐、首张结果时间、峰值内存。
  解码进程数从 2 / 4 / 8 测起并限制原生库线程；检测和 BioCLIP 的批大小分别定，不写死 32。
  目标是端到端 ≥ 1.67 张 / 秒。

**坐标与对焦点**
- 统一用"摆正后的原图归一化坐标（0–1）"存所有框和点，另存原图尺寸；帧、方形裁图、224 输入、界面显示都从它换算。
  要有覆盖竖拍、边缘框、方形补边的单元测试。
- `FocusLocation` 按它自带的宽高归一化再做旋转映射。exiftool 在拿不到对焦位置时会给画面中心：
  缺失、无效、恰为中心默认值的都记为"不可信"，不参与选主体，也不因此扣分。
- "框内或 3% 以内" = 对焦点到框的距离 ≤ 画面长边的 3%；多个框满足时取距离最近的，再按检测把握。

**鸟种**
- 地区修正在**全部 11,172 种的分布**上做，然后才取前五。结果里保存有效地点、日期及其来源（照片 / 所选地区）。
- 没有日期、没有先验、名录对不上时的回退要写明并有测试。"不确定 / 只报到属"的规则在实现时定成常量并写进文档。
- 中文名：名录矩阵里没有，需要一张"学名 → 中文名"的表（来源和许可在实现第 1 步查清，查不到的显示英文名）。

**单张识别**
- 上传先建稳定的照片 id（原图存数据目录，自生成文件名），后续用这个 id 提交"换主体框 / 手动框 / 补地区"，
  更新同一条历史。接口改为：
  `POST /api/singles`（上传）、`POST /api/singles/{id}/identify`（`{box?, region?}`）、
  `GET /api/singles`、`DELETE /api/singles/{id}`（连同存的原图一起删）、`DELETE /api/singles`。
- 单张和批量共用那一个模型工作线程；批量在批次边界让单张插队。

**安全**
- 前后端同源。`Host` 精确白名单（`127.0.0.1:端口`、`localhost:端口`）；带 `Origin` 的请求校验完整的
  scheme + host + port，拒绝 `null` 和异源；不配 CORS。写操作另要一个启动时生成的会话令牌（页面加载时下发，
  请求头带回）。图片 GET 只做 Host 校验。
- 上传限制体积和像素数。路径不拼进 shell 或 AppleScript（作为参数传）。
  启动时把缓存目录和数据目录规范化，若落在任何被扫描的文件夹内则拒绝。

**标星**
- 以调研产出的 `stars.py` 为准，不照搬原型里的演示算法。规格要写明：合格集合、名额分母与取整、并列顺序、
  封顶与保底的先后、保底可超额多少。只给已确认鸟种保底。连拍按拍摄时间（含亚秒）排序分组，
  缺时间的照片各自成组。清晰度缺失不等于零。

**界面**
- 排队行立即显示文件名；**选中**排队中的照片时，按需优先生成它的预览和拍摄信息。不做整批预扫。
- 每行按自己的状态渲染（并行处理会乱序完成、会失败），稳定的行 key，图片懒加载，短时间内的事件合并后再重绘。

**保留不变**
- exiftool 第一版保留：一个受控的常驻进程，串行提交，带响应匹配、超时、退出重启。
- React + Vite + TypeScript 保留。
- 模型清单保持可配置（主人要求），但第一版只验证 OWLv2 8 位一种检测模型，不做运行时热切换。

**验收补充**
